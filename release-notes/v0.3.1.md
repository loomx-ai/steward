Steward 0.3.1 turns release checks off in continuous integration.

## Release checks in CI

A CI job starts from a fresh home directory, so every run issued a new signature and was counted as a new installation, and nobody reads an advisory in a build log. Release checks are now off when `CI` is set, which covers GitHub Actions, GitLab, CircleCI, Travis, Buildkite and Bitbucket, or when `TF_BUILD` (Azure Pipelines), `JENKINS_URL` (Jenkins), `TEAMCITY_VERSION` (TeamCity) or `CODEBUILD_BUILD_ID` (AWS CodeBuild) is set. A value of `0` or `false` does not count as CI.

Nothing changes outside CI. `STEWARD_CHECKPOINT_DISABLE=1` and `DO_NOT_TRACK=1` still switch checks off everywhere, and `steward update` still downloads from GitHub releases directly.

Steward 0.4.0 runs scans on schedules, shows what every scan changed, covers dozens more AWS, Google Cloud and Azure products, and is much faster on large inventories.

## Highlights

- **Scheduled scans:** give a connection a schedule and Steward scans it on time, with overlap, catch-up, retry and auto-pause rules. Failures and pauses can be sent to a webhook, Slack, Feishu, DingTalk or WeCom channel.
- **Scan changes:** every scan records which resources it added, removed or modified. The scans pages show each run and its changes, and the console shows how fresh each connection's inventory is.
- **More resources:** inventory and cleanup for many more products on AWS, Google Cloud and Azure (listed below).
- **Faster on large inventories:** scans make far fewer cloud API calls, cleanup planning and execution no longer slow down quadratically with the number of steps, and the console loads less code.

## Scheduled scans and notifications

- Schedules choose the regions and resource kinds to scan, a time zone, and what happens when a run is still going, was missed, or fails. A schedule that keeps failing pauses itself and tells you why.
- Notification channels deliver schedule failures and pauses. Admins add them under **Settings** → **Notifications**.
- History retention applies to every scan. With a retention period set, finished scans older than it are deleted, both scheduled and manual. Steward always keeps each schedule's latest successful scan, and each connection's latest successful and latest complete manual scan. A retention of `0` keeps everything.

## New resource coverage

- **AWS:** Bedrock, Private CA, Secrets Manager, Cognito, Elastic Beanstalk, EventBridge Scheduler, IPAM, Client VPN, SNS subscriptions, AWS Config, WorkSpaces, EMR, API Gateway usage plans, resource groups, ELB trust stores, WAF associations and MSK topics.
- **Google Cloud:** Serverless VPC Access, Composer, Workflows, Cloud Scheduler, Cloud Build, Cloud Deploy, Vertex AI Workbench, Vertex AI, Certificate Authority Service, Memorystore for Memcached, NetApp Volumes, Kafka consumer groups, Eventarc, Cloud Workstations, Certificate Manager trust configs, Cloud Asset feeds, project organization policies and API Gateway API keys.
- **Azure:** Logic Apps, Automation, IoT Hub, SignalR, Web PubSub, App Configuration, Static Web Apps, DNS Private Resolver, Relay, Notification Hubs, Event Grid topics, Virtual Desktop, HDInsight clusters, custom Log Analytics tables and load balancer backend pools, which stay protected while a rule or interface uses them.

## Performance

- **Scans:** cloud reads that every region shard used to repeat are now shared within a scan. That covers Azure parent resources and region placement, Google Cloud Asset Inventory pages and the Cloud Identity directory, and Alibaba Cloud Resource Center searches. Lists that already return complete records are no longer followed by a read per resource. Throttled reads back off and retry instead of failing the shard.
- **Very large Azure parents:** a parent with more than about 1,400 child resources no longer fails its scan shard.
- **Cleanup:** dependency ordering, lifecycle grouping and execution bookkeeping now scale linearly with the number of steps. Execution workers no longer queue behind one lock after every step, and the progress stream pushes changes instead of the page polling the whole task.
- **Database:** SQLite runs in WAL mode with a separate read pool, keyword search uses FTS5 / pg_trgm indexes, PostgreSQL stores payloads as `jsonb`, and new indexes serve the inventory, findings and scan lists. An idle server no longer opens write transactions every second.
- **Console:** routes, locales and vendor code load as separate chunks, embedded assets are compressed once at startup, and the panorama renders only visible elements.

## Fixes

- **S3:** a bucket outside the home region is now checked for objects in its own region before deletion. Previously its contents were not checked, and the pre-delete check failed.
- **Resource queries:** missing fields, `NOT`, typed comparisons and dotted or colon tag keys behave the same in SQL as in memory.
- **Cleanup:** a throttled or transient read before a delete reschedules the action instead of failing it.
- **Scan changes:** number formatting and bookkeeping fields no longer count as an asset change.

## Upgrade notes

- The database migrates automatically on first start (migrations 00009–00017). Back up the database and `.steward/credential-master-key` before upgrading, as usual.
- Finish or cancel cleanup tasks created by 0.3.x before upgrading. Compatibility code for task formats written by older versions has been removed; create such tasks again after upgrading.
- Topology and inventory pages that were open during the upgrade may ask you to reload once.
- If you set a history retention period before, it now also applies to manual scans.
- PostgreSQL deployments without `STEWARD_DB_MAX_CONNS` now open at most 20 connections.

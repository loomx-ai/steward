## 完成后你会得到什么

你将连接一个云账号、扫描一个地域、找到一项已知资源，再查看它所在的网络和关联资源。完成后，你能说明这项资源属于哪个账号、Steward 最后一次发现它是什么时候，以及哪些依赖还需要核实。

本教程只连接、扫描和查看，不删除任何资源。截图使用阿里云示例数据。Steward 不会创建 `api-01` 等示例资源，请换成你自己的地域和资源 ID。

## 开始之前

准备以下条件：

- 已按[快速开始](../quick-start.md)启动 Steward，或已有 Steward Cloud 工作空间。
- 一个阿里云、AWS、Google Cloud 或 Azure 账号，以及具有所需读取权限的凭证。不需要删除权限。
- 一项你确定存在、且 Steward 支持盘点的地域资源，例如 ECS 实例。记下它的**地域、资源类型和云资源 ID**。

优先选择熟悉的小范围。暂时没有云账号时，可以先在 [LoomX 首页](https://loomx.ai/)体验示例演示，熟悉资源列表和关系视图；真实扫描需要你自己的云连接。

## 1. 添加并选中云连接

1. 打开用户菜单 → **设置** → **云连接** → **添加云连接**，选择**阿里云**。
2. 填写凭证，设置容易辨认的连接名称，然后创建。Steward 会先验证凭证。凭证类型见[连接云账号](../connections.md#credentials)。
3. 确认连接的地域列表与账号一致。
4. 返回主界面，在左上角的**当前云连接**中选中这个连接。

**检查结果**：当前连接是你准备盘点的账号，验证已通过，已知资源所在的地域在列表中。验证失败时，先检查凭证、有效期和错误详情，再继续。

## 2. 扫描已知资源所在的地域

1. 进入**扫描** → **开始扫描**。
2. 选择**选择部分地域**，勾选已知资源所在的地域。本例使用 `ap-southeast-1`。
3. **资源类型**留空，扫描该地域内全部已索引资源类型。
4. 点击**创建扫描**，页面进入扫描详情。

全局资源不属于任何地域；需要时另外勾选**全局**。

**检查结果**：所有目标都已完成，没有失败项。有失败项时，按日志修正原因后点击**重试**。参阅[失败项意味着什么](../scans.md#progress)。

## 3. 找到并核对那项资源

1. 进入**资源**，搜索已知的云资源 ID。用 ID 搜索可以区分同名资源。
2. 点击匹配的资源，打开详情。

<figure class="docs-figure"><a href="../../../assets/inventory-zh.png" target="_blank" rel="noreferrer" aria-label="核对资源列表中的身份和最后发现时间（打开原图）"><img src="../../../assets/inventory-zh.png" alt="资源列表展示名称、云资源 ID、类型、地域和最后发现时间" width="1440" height="960"></a><figcaption>以资源 ID 和地域确认身份，以最后发现时间判断数据新旧；名称只用于辅助识别。</figcaption></figure>

对照云控制台或你事先记下的信息，检查：

1. 当前连接、地域和资源类型正确。
2. 云资源 ID 一致，名称和关键属性符合预期。
3. 最后发现时间与刚才的扫描相符。

**检查结果**：你能把 Steward 中的一条记录对应到云端的同一项资源。找不到时，先检查连接、地域和扫描失败项，不要直接认定资源已不存在。

## 4. 查看网络位置与关联

1. 在资源详情中点击**在资源全景中查看**，核对地域、VPC 和交换机。
2. 点击画布工具栏中的**显示关系连线**，或在资源详情中切换到**关系**标签页。

<figure class="docs-figure"><a href="../../../assets/relationships-zh.png" target="_blank" rel="noreferrer" aria-label="示例中的两台实例共用负载均衡和安全组（打开原图）"><img src="../../../assets/relationships-zh.png" alt="示例关系图中 public-gateway 指向 api-01 和 api-02，两台实例共用 application-policy 安全组" width="1440" height="960"></a><figcaption>本例中，两台实例共用负载均衡和安全组。确定后续清理审查的范围前，先记下这些共享关系。</figcaption></figure>

目标不在 VPC 中时，在资源详情中查看属性和已有关系即可，不必复现截图中的网络层级。

**检查结果**：你能说明资源所在的位置，以及 Steward 发现了哪些关联资源。没有连线时，先确认相关资源已扫描；参阅[如何使用这些关系](../topology.md#interpret)。

## 5. 记录盘点结论

为你的资源写一条记录：

| 项目 | 记录内容 |
| --- | --- |
| 资源身份 | 连接、地域、资源类型、云资源 ID |
| 数据时间 | 最后发现时间，以及对应的扫描任务 |
| 扫描范围 | 覆盖的地域和资源类型，以及仍未覆盖的部分 |
| 关联情况 | 已确认的共享资源，以及待核实的依赖 |

到这里，你已完成一次可以核验的资源盘点。云端发生变更后，先重新扫描受影响的范围，再比较资源记录。

## 结果与预期不一致时

| 现象 | 先检查什么 |
| --- | --- |
| 连接正常，但某类资源扫描失败 | 该资源 API 的读取权限。连接验证不会检查每一项资源权限。 |
| 搜不到已知资源 | 当前连接、地域、资源类型，以及该目标的扫描项结果 |
| 属性仍是修改前的值 | 最后发现时间；重新扫描后再刷新页面 |
| 关系图缺少预期连线 | 关联资源是否已扫描，以及 Steward 的关系规则是否覆盖这种关系 |

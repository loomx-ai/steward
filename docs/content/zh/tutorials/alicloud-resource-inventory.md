一份可用的阿里云资源清单，应当能说明覆盖了哪个账号、哪些地域、何时发现资源，以及哪些读取失败。本教程使用 LoomX 的 Steward 完成这些核对，不执行资源清理。

Steward 结合资源中心与云产品查询 API 发现资源。实际覆盖取决于支持的资源类型、地域、权限与资源中心的收集状态。资源总数不能单独证明整个账号已被完整盘点。

## 开始之前

- [安装并启动 Steward](../quick-start.md)，或打开 Steward Cloud 工作空间。
- 选择一个获授权读取的阿里云账号，准备专用 RAM 身份的 AccessKey 或完整 STS 临时凭证。
- 在阿里云控制台记录一个已有 ECS 实例的账号、地域与实例 ID，无需创建新资源。
- 确认资源中心已开通，并核对[阿里云盘点权限](../alicloud.md)。先取得所选资源类型的读取权限即可。

示例界面中的 `api-01` 是演示记录。实际操作时，请使用自己账号中已知的实例 ID。

## 1. 确认连接的账号身份

打开用户菜单 → 设置 → 云连接 → 添加连接，选择 **阿里云**，并选择与账号一致的中国站或国际站。站点决定账号体系，不是资源地域。

输入 AccessKey ID 和 AccessKey Secret；使用 STS 时，另外填写同次签发的 Security Token 和到期时间。若界面提供浏览器授权，也可按授权流程连接。验证后检查账号身份，将连接命名为可辨认的名称，例如「阿里云 · 测试环境」。

**结果核对：** 连接身份与已知资源所属账号一致，地域列表包含目标地域。连接验证成功，不代表已经拥有每种资源 API 的读取权限。

## 2. 先扫描一个已知地域

切换到该连接，打开 **扫描**，选择已知实例所在的地域，例如 `cn-hangzhou`，开始扫描。也可以从已知 VPC 或交换机开始，先验证一个较小的范围。

检查目标状态与扫描日志。出现权限、限流或服务错误时，处理失败项后重试。任务已经结束但仍有失败目标时，清单依然存在缺口。

打开 **资源**，搜索实例原生 ID，核对资源类型、地域、VPC、交换机、属性与最后发现时间。

**结果核对：** 在正确连接和地域下找到已知实例，关键属性与阿里云控制台一致，相关扫描目标没有未处理的失败项。

## 3. 扩大范围并记录覆盖情况

首次核对通过后，再扫描其他已启用地域，以及所需的全局资源。地域资源与全局资源应分别检查；一个地域扫描成功不能代表整个账号已盘点完成。

需要盘点另一个阿里云账号时，为它建立独立连接，再重复身份、扫描与资源核对。切换账号应新建连接；「替换凭证」用于维护原有身份的凭证。

在团队现有记录工具中保存以下信息：

| 账号 | 扫描范围 | 数据时间 | 已核对的样本 | 剩余缺口 |
| --- | --- | --- | --- | --- |
| 实际账号身份 | 地域列表，是否包含全局资源 | 扫描任务和最后发现时间 | 已在阿里云中核对的资源 ID | 失败类型、权限缺口或收集延迟 |

**结果核对：** 能说明已覆盖的范围与仍未确认的部分，其他人可用相同账号和资源 ID 复查结果。

## 排查缺失的阿里云资源

| 现象 | 优先检查 |
| --- | --- |
| 提示 `ServiceNotEnabled` | 资源中心是否开通，以及首次资源收集是否完成。 |
| 验证成功，扫描仍报权限错误 | 失败目标的具体 API 与 RAM Action；资源中心权限和产品读取权限都需要核对。 |
| 某个实例缺失 | 当前账号、地域、资源类型和扫描范围是否包含该实例；用原生 ID 搜索。 |
| 新资源或属性尚未更新 | 资源中心收集可能存在延迟；检查产品 API 错误并稍后重扫。 |
| 部分地域没有数据 | 地域列表与目标范围、读取权限，以及该地域的扫描状态。 |
| 关系图不完整 | 关联资源是否也在扫描范围内，相关类型是否受支持。 |

详细凭证、资源中心与 API 要求见[阿里云集成参考](../alicloud.md)。查看网络位置可继续阅读[资源关系](../topology.md)。准备删除之前，先完成[清理依赖审查](./review-cleanup-dependencies.md)。

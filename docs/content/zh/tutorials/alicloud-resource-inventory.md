一份有用的阿里云资源清单，应当说明覆盖了哪个账号和哪些地域、资源何时被发现，以及哪些读取失败了。本教程使用 LoomX 的 Steward 建立这份记录，不执行任何清理。

Steward 结合资源中心与云产品查询 API 发现资源。能发现什么取决于支持的资源类型、权限、地域和资源中心的收集状态，因此资源总数不能单独证明整个账号已完整盘点。

## 开始之前

- [安装并启动 Steward](../quick-start.md)，或打开 Steward Cloud 工作空间。
- 获授权 RAM 身份的 AccessKey，或一组完整的 STS 临时凭证。
- 一台已有的 ECS 实例。在阿里云控制台记下它的账号、地域和实例 ID，无需新建资源。
- 已开通资源中心，并已配置[阿里云盘点权限](../alicloud.md)。本练习只需要读取权限。

截图中的 `api-01` 是示例记录。实际操作时，请使用你自己账号中的实例 ID。

## 1. 确认连接的账号身份

1. 打开用户菜单 → **设置** → **云连接** → **添加云连接**，选择**阿里云**。
2. 选择与账号一致的**中国站**或**国际站**。站点决定账号体系，与资源地域无关。
3. 填写 AccessKey ID 和 AccessKey Secret；使用 STS 时，另外填写同次签发的 Security Token 和到期时间。界面提供**用浏览器登录**时，也可以改用浏览器授权。
4. 设置容易辨认的连接名称，例如「阿里云 · 测试环境」，然后创建。Steward 会先验证身份。

**检查结果**：连接身份与已知实例所属账号一致，地域列表包含目标地域。验证只确认身份，不代表每种资源 API 都可读取。

## 2. 先扫描一个已知地域

1. 在**当前云连接**中选中该连接。
2. 进入**扫描** → **开始扫描**，选择**选择部分地域**，勾选实例所在的地域，例如 `cn-hangzhou`。想先验证更小的范围，可以改选**指定 VPC / vSwitch**，选择一个已知的 VPC 或交换机。
3. 点击**创建扫描**，检查目标状态和日志。出现权限、限流或服务错误时，处理后点击**重试**。
4. 进入**资源**，搜索实例的云资源 ID，对照阿里云控制台核对资源类型、地域、VPC、交换机、属性和最后发现时间。

**检查结果**：在正确的连接和地域下找到已知实例，关键属性与控制台一致，相关扫描项没有未处理的失败。扫描已结束但仍有失败项时，清单依然存在缺口。

## 3. 扩大范围并记录覆盖情况

1. 扫描其他已启用地域以及所需的全局资源，例如选择**全部启用地域 + 全局**。地域资源和全局资源分别核对；一个地域扫描成功，不代表整个账号已盘点完成。
2. 盘点另一个阿里云账号时，为它新建连接，再重复身份和资源核对。**替换凭证**只用于更新同一身份的凭证；切换账号需要新建连接。
3. 在团队现有的记录工具中保存结果：

| 账号 | 扫描范围 | 数据时间 | 已核对的样本 | 剩余缺口 |
| --- | --- | --- | --- | --- |
| 实际账号身份 | 地域列表，是否包含全局 | 扫描任务和最后发现时间 | 已在阿里云中核对的资源 ID | 失败类型、权限缺口或收集延迟 |

**检查结果**：其他人可以用相同的账号和资源 ID 复查结果，并区分已核实的覆盖范围与读取失败或收集延迟。

## 排查缺失的阿里云资源

| 现象 | 优先检查 |
| --- | --- |
| 提示 `ServiceNotEnabled` | 资源中心是否开通，以及首次资源收集是否完成。 |
| 验证成功，扫描仍报权限错误 | 失败的 API 及对应的 RAM Action；资源中心权限和产品读取权限都要核对。 |
| 某个实例缺失 | 当前账号、地域、资源类型和扫描范围；用云资源 ID 搜索。 |
| 新资源或属性尚未更新 | 资源中心收集延迟和产品 API 错误；稍后重新扫描。 |
| 部分地域没有数据 | 地域发现、所选范围、读取权限，以及该地域的目标状态。 |
| 关系图不完整 | 关联资源是否也已扫描，相关类型是否受支持。 |

下线一个应用，可能影响其他应用仍在使用的资源。本教程结合 Steward 的资源清单、关系图和清理审查，核对这条边界。最终结果是一份审查决定，本次练习不执行删除。

示例使用阿里云样本资源：`api-01` 与 `api-02` 两个实例共用 application vSwitch，名为 `public-gateway` 的负载均衡也在待审查范围内。这些记录仅用于说明，不会由 Steward 自动创建到你的账号中。

## 1. 先获得当前资源清单

选择正确的云连接，扫描相关范围。包含周边网络与关联资源，并检查扫描失败项和资源最后发现时间。可能的依赖位于范围之外时，先补全相应扫描。

使用原生 ID 在云控制台核对资源。不同账号和地域可能使用相同命名，名称不能单独证明身份。[首次资源盘点教程](./first-inventory.md)包含完整核对步骤。

**结果核对：** 你能说明扫描范围、观测时间与尚未解决的失败项。未扫描的区域不能视为空范围。

## 2. 检查共享关系

打开资源详情中的关系视图，或在资源全景中定位资源并显示关系连线。检查与待删除资源相连的节点，也检查准备保留的节点。

<figure class="docs-figure"><a href="../../../assets/relationships-zh.png" aria-label="查看示例中的共享负载均衡和安全组"><img src="../../../assets/relationships-zh.png" alt="阿里云示例数据：api-01 与 api-02 共用负载均衡和安全组" width="1440" height="960"></a><figcaption>共享资源将待清理目标与可能需要保留的实例连接起来。截图使用示例数据。</figcaption></figure>

在示例中，删除 `api-01` 并不能说明共享 vSwitch 或安全组已不再被使用。打开另一个实例，确认其负责人是否仍需要它。关系图不完整或数据较旧时，应当核对云端状态。

**结果核对：** 已识别目标范围之外、仍依赖选中资源的对象。关系连线来自扫描数据与当前支持的规则，缺少连线不能证明没有依赖。

## 3. 创建审查任务，核对实际目标

将准备处理的资源加入清理列表，创建清理任务。创建任务不会执行删除，本次停留在审查阶段。

检查实际资源 ID 与计划执行的动作。账号、项目、地域或分组等宽范围目标，可能解析出比名称暗示的更多资源。也要检查保留项、跳过项，以及通过所属控制器或资源栈处理的资源。

示例任务选择了 `api-01`、`public-gateway` 和 application vSwitch。未选中的 `api-02` 仍需要该 vSwitch，因此 vSwitch 删除被阻断。

## 4. 决定目标范围

| 发现 | 需要记录的决定 |
| --- | --- |
| `api-02` 必须保留 | 从目标中移除共享 vSwitch，重新审查更新后的计划。 |
| 负责人确认 `api-02` 也可移除 | 将其加入视为一次新的范围决定，检查它自己的依赖和扩大的目标清单。 |
| 依赖或负责人不明确 | 暂不执行，先确认归属和云端状态。 |
| 某资源被保留或跳过 | 记录保留原因，以及是否需要单独跟进。 |

不要仅为消除阻断项而加入更多资源。扫描覆盖不完整的警告未必会阻止执行，没有阻断项也不保证所有依赖都已被发现。

## 5. 以审查记录结束

为实际任务记录云连接、准确目标 ID、需要保留的资源、待确认依赖，以及审查所依据的扫描。可接受的结论包括“保留共享网络，仅审查实例”，或“补扫缺失地域后再决定是否执行”。

明确拟处理范围和未解决的问题，就完成了本教程，无需运行删除。

之后确实决定执行时，请跟随[清理执行与结果核验指南](../cleanup.md#execute)。云平台保护和保留规则仍然适用，具体限制见 [阿里云](../alicloud.md)、[AWS](../aws.md)、[Google Cloud](../gcp.md) 或 [Azure](../azure.md)。执行后检查逐资源结果并重新扫描。暂停任务不会撤销已经发出的请求，也不能恢复已删除资源。

下线一个应用，可能影响其他应用仍在使用的资源。本教程结合 Steward 的资源清单、关系图和清理审核，找出这条边界。最终产出一份书面的范围决定，不删除任何资源。

示例使用阿里云样本资源：`api-01` 与 `api-02` 两台实例共用 application 交换机，名为 `public-gateway` 的负载均衡也在审查范围内。这些只是示例记录，Steward 不会在你的账号中创建它们。

## 开始之前

- 一个云连接，具备待审查范围的读取权限。如果还没扫描过，先完成[第一次资源盘点](./first-inventory.md)。
- 准备移除的资源，并已知它们的云资源 ID。

## 1. 先获得当前资源清单

1. 在**当前云连接**中选中正确的连接。
2. 进入**扫描** → **开始扫描**，扫描相关范围，包括周边网络和关联资源。
3. 在扫描详情页检查失败项，再核对待审查资源的最后发现时间。可能的依赖位于扫描范围之外时，一并扫描。
4. 用云资源 ID 在云控制台逐项核对。不同账号和地域可能沿用相同的命名，仅凭名称无法确认身份。

**检查结果**：你能说明扫描范围、扫描时间以及尚未解决的失败项。未扫描的区域不能视为空。

## 2. 检查共享关系

1. 在**资源**中打开资源详情并切换到**关系**，或在**资源全景**中定位资源并点击**显示关系连线**。
2. 沿连线检查准备删除的资源，也检查准备保留的资源。

<figure class="docs-figure"><a href="../../../assets/relationships-zh.png" aria-label="查看示例中的共享负载均衡和安全组"><img src="../../../assets/relationships-zh.png" alt="阿里云示例数据：api-01 与 api-02 共用负载均衡和安全组" width="1440" height="960"></a><figcaption>共享资源把待清理目标与可能需要保留的实例连在一起。截图使用示例数据。</figcaption></figure>

在示例中，删除 `api-01` 并不说明它所在的交换机或安全组已无人使用。打开 `api-02`，向其负责人确认是否仍需要它。关系图看起来不完整或数据较旧时，到云控制台核对。

**检查结果**：你已列出目标范围之外、仍依赖所选资源的对象。缺少连线不能证明没有依赖，参阅[如何使用这些关系](../topology.md#interpret)。

## 3. 创建审查任务，核对实际目标

1. 在**资源**中勾选准备移除的资源，点击**加入资源清单 (N)**。
2. 点击**资源清单** → **创建清理任务**，再点击**确定**。创建任务不会删除任何资源。
3. 在任务页停在**开始清理**之前。在**资源结果**中核对资源 ID 和计划动作，在**清理目标**中查看每个目标实际解析出的资源。

账号、项目、地域或分组等宽范围目标，可能解析出比名称所示更多的资源。还要检查保留资源、跳过的资源，以及通过所属控制器或资源栈处理的资源。

示例任务选择了 `api-01`、`public-gateway` 和 application 交换机。未选中的 `api-02` 仍需要该交换机，因此交换机的删除被阻断。

<figure class="docs-figure"><a href="../../../assets/cleanup-dependency-zh.svg" aria-label="检查清理选择范围之外的依赖"><img src="../../../assets/cleanup-dependency-zh.svg" alt="未选中的 api-02 使用已选中的 application 交换机，阻断其删除" width="640" height="700"></a><figcaption>范围之外的依赖会改变可删除的目标。请在自己的任务中核对资源 ID。</figcaption></figure>

**检查结果**：你已读完**执行阻断项**中的每一项，并清楚每项保护的是哪个资源。

## 4. 决定目标范围

| 发现 | 需要记录的决定 |
| --- | --- |
| `api-02` 必须保留 | 从目标中移除共享交换机，创建新任务并重新审核。 |
| 负责人确认 `api-02` 也可移除 | 把加入它视为一次新的范围决定，检查它自己的依赖和扩大后的目标清单。 |
| 依赖或负责人不明确 | 暂不执行，先确认归属和云端状态。 |
| 某资源被保留或跳过 | 记录保留原因，以及是否需要单独跟进。 |

不要仅为消除阻断项而加入资源。没有阻断项也不保证所有依赖都已发现，参阅[扫描覆盖说明](../cleanup.md#review)。

## 5. 以审查记录结束

为你的任务记录云连接、准确的目标 ID、需要保留的资源、待确认的依赖，以及审查所依据的扫描。可接受的结论包括“保留共享网络，只审查实例”，或“补扫缺失地域后再决定是否执行”。

明确了拟处理范围和未解决的问题，就完成了本教程，无需执行删除。

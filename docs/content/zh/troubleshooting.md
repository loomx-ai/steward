从最接近你遇到的现象开始排查。各云指南中还有针对该云常见错误的排查说明：[阿里云](./alicloud.md) · [AWS](./aws.md) · [Google Cloud](./gcp.md) · [Azure](./azure.md)。

## 资源清单与扫描

| 现象 | 检查项 |
| --- | --- |
| 资源清单为空 | 添加连接不会自动扫描。确认选中了正确的连接，然后[开始扫描](./scans.md#scope)，并在扫描详情中查看失败项。 |
| 确定存在的资源没有出现 | 用云资源 ID 搜索。检查连接、地域和资源类型，确认扫描包含了该地域；全局资源还需要选择**全局**。打开扫描详情查看失败项。 |
| 新建的资源或刚做的修改还没出现 | 部分数据源存在同步延迟，例如阿里云资源中心和 Google Cloud Asset Inventory。稍后重新扫描。 |
| 属性仍是旧值 | 对比**最后发现时间**与修改时间。刷新页面不会重新扫描，请重新扫描相应范围。 |
| 部分扫描项因权限错误失败 | 连接缺少这些资源类型的读取权限。连接验证只检查身份。按错误信息补充权限（参见云指南），再对扫描执行**重试**。 |
| 同一名称出现多次 | 对比连接、地域、资源类型和云资源 ID。 |
| 缺少预期的关系连线 | 确认两项资源都已扫描，且 Steward 支持这种关联。没有连线不代表没有依赖。参见[资源关系](./topology.md)。 |

## 云连接

| 现象 | 检查项 |
| --- | --- |
| 验证失败 | 展开错误详情查看错误码和请求 ID，检查权限、到期时间，以及密钥 ID 与密钥是否配对。 |
| 连接提示需要重新授权 | 临时凭证已过期，或浏览器登录被撤销、已到期。使用**替换凭证**。参见[维护连接](./connections.md#maintain)。 |
| 浏览器登录一直无法完成 | 浏览器和 Steward 服务必须在同一台机器上。远程服务请使用 AccessKey 或 [OIDC](./oidc.md)。 |
| 连接缺少某个地域 | 刷新地域列表，按云指南检查地域查询权限，并确认该地域已在云账号中开通。 |

## 清理

| 现象 | 检查项 |
| --- | --- |
| 任务出现阻断项 | 任务之外的资源仍依赖某个目标，或某项依赖无法确认。参见[审核阻断项与保留资源](./cleanup.md#review)。 |
| 删除时报权限错误 | 在**清理日志**中查看该资源的记录。读取和扫描不需要删除权限，所以这类权限经常缺失。补充权限后继续执行任务。 |
| 清理后资源仍在计费 | 查看任务结果中的保留和跳过资源，然后重新扫描。 |

## 自行部署的服务

| 现象 | 检查项 |
| --- | --- |
| 服务拒绝监听网络地址 | 本机模式只接受回环地址。按[为团队开放访问](./deployment.md#network)切换到 Token 模式。 |
| 重启、恢复或迁移后凭证无法解密 | Steward 使用了不同的凭证密钥。把原来的 `credential-master-key` 放回数据目录（`~/.steward` 或 `STEWARD_HOME`），或将 `STEWARD_CREDENTIAL_MASTER_KEY` 设为原值。不要用新密钥覆盖旧密钥。 |
| 升级或迁移后资源清单变空 | Steward 读取了另一个数据目录。确认 `STEWARD_HOME` 指向之前使用的目录。早期版本把数据放在工作目录下的 `./.steward`；如果启动时提示「正在使用 … 中的数据」，请把该目录移到 `~/.steward`，或将 `STEWARD_HOME` 设为该目录。 |

## 反馈问题

在 [GitHub Issues](https://github.com/loomx-ai/steward/issues) 提交问题时，请附上 Steward 版本（`steward version`）、复现步骤、错误码和脱敏后的请求 ID。不要附带令牌、AccessKey、数据库或加密密钥。

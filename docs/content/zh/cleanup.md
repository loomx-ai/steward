准备用 Steward 删除云资源时阅读本页。清理分五个阶段，只有最后一步确认后才会真正删除：

1. **选择目标**，放入资源清单。
2. **创建清理任务**。Steward 把目标解析为具体资源并检查依赖，此时不会删除任何资源。
3. **审核**阻断项、保留资源和跳过的资源。
4. 点击**开始清理**并**确认执行**。Steward 开始调用云厂商的删除 API。
5. **核对**结果并重新扫描。

开始之前，先扫描准备清理的完整范围。清理只会在 Steward 已发现的资源之间检查依赖（参阅[何时重新扫描](./scans.md#freshness)）。

<span id="select"></span>

## 1. 选择目标并创建任务

先选少量已确认不再需要的资源。目标会暂存在**资源清单**中，资源清单属于当前云连接；切换连接时，Steward 会先询问，确认后清空清单。

**从资源页面：**

1. 在**资源**中勾选要清理的行。
2. 点击**加入资源清单 (N)**。这些行会标记为**待清理**。
3. 点击右下角的**资源清单**，核对目标，移除不需要的项。
4. 点击**创建清理任务**。在**新建清理任务**中核对**清理目标**，再点击**确定**。

**从资源全景：**右键点击地域、VPC、交换机或资源，或打开其详情，选择**加入资源清单**（分组选择**全部加入资源清单**）。需要一次选多个节点时，在画布工具栏选择**框选**，拖动框住节点后点击**添加所选项**。然后打开**资源清单** → **创建清理任务** → **确定**。

**从清理页面：**点击**新建任务**，通过**添加单个资源**（输入资源 ID）或**从资源全景选择**添加目标，再点击**确定**。

**检查结果**：页面进入清理任务详情。此时还没有删除任何资源。

账号、项目、地域或分组目标可能解析出远多于名称所示的资源。查看任务的资源数，并在**清理目标**标签页中查看每个目标实际解析出的资源。

<span id="review"></span>

## 2. 审核阻断项与保留资源

开始清理前先审核任务。只有任务没有阻断项时，才会出现**开始清理**按钮。

| 查看位置 | 检查内容 |
| --- | --- |
| **执行阻断项**（任务页顶部） | 每个阻断项及其依据。**查看 N 个阻断资源**会把**资源结果**筛选为被阻断的资源；**加入 N 个依赖资源**可把依赖资源加入任务（见下方示例）。 |
| **资源结果** | 每项资源的 ID、地域和计划执行的**动作**。**状态原因**会说明哪些资源随控制器一并删除、哪些被跳过（例如不支持的类型）、哪些脏资源会在清理时忽略。 |
| 保留和跳过的资源 | 每项资源保留的原因，以及是否可能继续计费。 |
| **清理提醒** | 扫描覆盖不完整。这是提醒而不是阻断项，见下方说明。 |

<aside class="docs-note">扫描覆盖不完整不会阻止<strong>开始清理</strong>：Steward 会基于已发现的资源执行清理，可能遗漏未扫描地域或资源类型中的依赖。没有阻断项不代表所有依赖都已发现，没有关系连线也不代表资源无人使用。请先扫描相关范围。</aside>

### 哪些情况会产生阻断项

| 阻断项 | 含义 | 处理方式 |
| --- | --- | --- |
| 清理依赖尚未核验 | 云厂商报告了 Steward 无法核验的依赖。通过所属控制器删除的资源也受此保护。 | 核对资源 ID 和依据，重新扫描该资源及其依赖。 |
| 任务外的资源仍在使用目标 | 你选中的网络、密钥或身份仍被未选中的资源使用，例如 AWS KMS 密钥或 IAM 角色、Google Cloud KMS 密钥或服务账号、Azure 托管身份。即使直接选中了该目标，也会阻断。 | 把依赖资源加入任务；或者保留该目标，创建不含它的新任务。 |
| 密钥或身份缺少完整扫描 | 删除密钥或身份，要求该连接的所有启用地域和全局范围都已完整扫描，因为未扫描的资源可能仍在使用它。 | 选择**全部启用地域 + 全局**执行扫描，并处理所有失败项。 |
| 连接自身使用的身份 | Steward 不会删除连接正在使用的身份（见下表），否则会在清理中途撤销自己的访问权限。 | 创建不含它的新任务。 |
| 控制器无法清理 | 选中的控制器无法清理时，依赖它的子资源删除步骤也会被阻断。 | 如需单独清理受支持的子资源，只选择这些子资源、不选控制器，然后审核新任务。 |

新发现的依赖问题会使已审核的计划失效。开始清理前，请重新审核更新后的任务。

需要完整扫描的密钥和身份：

| 云厂商 | 资源类型 |
| --- | --- |
| AWS | KMS 密钥、IAM 角色、IAM 用户 |
| 阿里云 | KMS 密钥、RAM 角色 |
| Google Cloud | Cloud KMS 密钥及密钥版本、服务账号 |
| Azure | 用户分配的托管身份、Key Vault 保管库及其密钥 |

连接自身使用的身份始终受保护：

| 云厂商 | 受保护的资源 |
| --- | --- |
| AWS | 连接背后的 IAM 用户或角色、其用户组、附加的托管策略和实例配置文件 |
| 阿里云 | RAM 用户或角色、用户所在的用户组，以及直接或经用户组附加到它们的自定义权限策略 |
| Google Cloud | 服务账号及其密钥 |
| Azure | 授予连接服务主体的角色分配 |

处理方式取决于哪些资源需要保留：

- **`api-02` 必须保留**：创建不含该交换机的新任务。从**资源清单**（或**新建清理任务**的**清理目标**）中移除交换机，创建任务后重新审核。
- **`api-02` 也应删除**：点击**加入 N 个依赖资源**，核对列表后点击**加入并更新任务**。任务的清理范围和阻断项可能随之变化，需要重新审核。

加入资源是一项新的范围决定。不要仅为了消除阻断项而加入资源，也不要用[**标记为脏资源**](./resources.md#selection)绕过阻断项。

## 3. 确认执行

1. 在任务页点击**开始清理**。
2. 在**破坏性操作确认**中设置**并发度**，即同时删除的资源数，范围 1–100，默认 20。遇到云厂商限流时调低。
3. 如果任务目标是整个云账号，或账号、项目、订阅、地域范围，逐个输入目标的完整名称。
4. 如果出现**我已审核此清理任务及其影响。**，勾选它。
5. 点击**开始清理**。

随后 Steward 按依赖顺序调用云厂商删除 API，并回读每项结果。

<span id="results"></span>

## 4. 核对结果

- **资源结果**显示每项资源的状态。排查失败时，打开**清理日志**，使用**按资源 ID 过滤**。
- **暂停**会停止尚未开始的资源；正在删除的资源会继续完成，完成前任务显示**暂停中**。暂停不会撤销已发出的请求，也不会恢复已删除的资源。点击**恢复**继续执行。
- 有资源失败时，修正原因后点击**继续**。Steward 会重试失败的资源并继续尚未开始的资源，已完成的资源不会重复执行。

任务结束后，重新扫描相关范围，检查保留资源和账单。**审计**页记录每次清理的操作者、动作和结果。

## 云厂商保护

- **Google Cloud**：[清理范围与删除保护](./gcp.md#删除保护)，包括 VM 磁盘自动删除、非空存储桶和 GKE 工作负载 finalizer。
- **Azure**：[清理保护](./azure.md#清理保护)，包括管理锁、VM 挂载设置、存储空资源要求和托管资源限制。
- **阿里云**和 **AWS**：清理行为与保护见[阿里云](./alicloud.md)和 [AWS](./aws.md)。

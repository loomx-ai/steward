Steward 帮你回答关于云账号的三个问题：有哪些资源在运行、资源之间如何依赖、清理会影响什么。目前支持阿里云、AWS、Google Cloud（GCP）和 Microsoft Azure，可以自行部署，也可以注册使用 Steward Cloud。

常见用法：

- **盘点存量资源**：扫描你选择的账号和地域，按名称、ID、类型或属性查找资源。
- **检查共享依赖**：从网络全景进入，沿 Steward 发现的关联查看上下游资源。
- **先审查、再清理**：把资源放进清理任务，处理阻断项，确认无误后再执行删除。

第一次使用？读完本页后，跟随[第一次资源盘点](./tutorials/first-inventory.md)，用一项你已有的资源走一遍流程。

## Steward 如何工作

Steward 通过**云连接**读取资源，记录每次**扫描**发现的内容，再基于这些记录生成资源清单和关系视图。

<figure class="docs-figure"><a href="../../assets/scan-data-flow-zh.svg" target="_blank" rel="noreferrer" aria-label="扫描如何生成资源清单和关系图（打开原图）"><img src="../../assets/scan-data-flow-zh.svg" alt="云厂商 API 经指定范围的扫描生成资源记录；资源清单和关系图读取这些扫描结果。云端变更后需要再次扫描。" width="640" height="650"></a><figcaption>扫描记录资源及其被发现的时间，资源清单和关系图展示的就是这些记录。</figcaption></figure>

以下三种操作会访问你的云账号，只有最后一种会改变云上资源：

| 操作 | 作用 |
| --- | --- |
| 验证连接 | 确认凭证属于哪个云身份 |
| 扫描 | 在你选择的范围内调用只读接口 |
| 确认执行清理任务 | 对审查过的资源发起删除请求 |

## 云连接与资源身份

一个**云连接**保存一个云身份的凭证，对应一个阿里云账号、AWS 账号、Google Cloud 项目或 Azure 订阅。资源、扫描和清理任务都归属于某个连接，查看结果前先确认当前选中的是哪个连接。

资源名称可能重复或变更，因此 Steward 用以下四项确定一项资源：

| 字段 | 回答的问题 | 示例 |
| --- | --- | --- |
| 云连接 | 哪个账号、用哪个身份访问？ | 名为「生产账号」的阿里云连接 |
| 地域 | 资源在哪里？ | `ap-southeast-1` |
| 资源类型 | 是什么资源？ | ECS 实例、VPC、安全组 |
| 云资源 ID | 具体是哪一项？ | `i-demo-api01` |

截图中的 `api-01` 是名称，`i-demo-api01` 是云资源 ID。

## 读懂扫描结果

资源清单展示的是最近一次扫描看到的内容，不是云端的实时状态。每项资源都有**最后发现时间**，即扫描最后一次观察到它的时间。扫描之后如果在云控制台做了修改，Steward 会一直显示修改前的状态，直到你重新扫描相应范围。刷新浏览器不会触发扫描。

判断盘点是否完整，要看两点：

- **范围**：扫描包含了哪些地域、全局资源和资源类型。扫描某个地域不会同时扫描全局资源（如 RAM 身份）或其他地域；需要时请同时选择**全局**。详见[扫描范围](./scans.md#scope)。
- **结果**：每个扫描项是否都已完成，有没有因权限或接口错误而失败。

结果为空或偏少，可能是范围不对、缺少权限或该资源类型尚未覆盖，不一定是云上真的没有资源。下结论之前，先打开扫描详情查看。

## 资源全景与关系连线

**资源全景**按账号、地域和网络（VPC、交换机）排布资源，帮你找到资源所在的位置。**关系连线**进一步展示 Steward 能识别的关联，例如负载均衡指向实例、实例使用安全组。

<figure class="docs-figure"><a href="../../assets/topology-zh.png" target="_blank" rel="noreferrer" aria-label="Steward 资源全景按网络位置组织资源（打开原图）"><img src="../../assets/topology-zh.png" alt="Steward 的 VPC 全景中，应用实例与数据库分布在不同交换机内" width="1440" height="960"></a><figcaption>示例数据：应用实例与数据库位于不同交换机。网络分组说明资源在哪里，关系连线说明资源如何关联。</figcaption></figure>

同处一个 VPC 或交换机，只说明资源的网络位置相同，并不代表彼此依赖。关系连线来自已扫描的资源和 Steward 支持的规则，因此没有连线也不能证明不存在依赖。[资源关系](./topology.md)介绍如何浏览全景并聚焦单个资源。

## 从选择到删除

清理分阶段逐步收窄范围，直到第三步才会删除资源：

| 阶段 | 需要确认什么 | 是否删除资源 |
| --- | --- | --- |
| 加入资源清单 | 哪些资源值得进一步查看 | 否 |
| 创建清理任务 | 任务实际解析出的资源，以及阻断项、警告和保留资源 | 否 |
| 确认执行 | 审查后的范围是否符合预期 | 是 |
| 核对结果 | 哪些资源已删除、失败或被保留 | 删除请求可能仍在进行 |

清理任务会检查依赖关系，以及每项删除是否受支持。阻断项必须处理，警告也要阅读，尤其是扫描覆盖不完整的提示。执行开始后，暂停可以停止后续请求，但无法撤回已发出的请求，也无法恢复已删除的资源。

[清理资源](./cleanup.md)用一个被阻断的清理示例，演示审查和执行的完整步骤。
